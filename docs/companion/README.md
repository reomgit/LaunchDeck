# Browser companion

LaunchDeck serves a synchronized virtual deck on your Mac's local network. Open **Companion**, click **Start Companion**, and connect a phone or tablet to the same trusted network. Scan the desktop QR code or open one of the displayed network addresses. The `127.0.0.1` address works only on the Mac itself. If multiple network interfaces are active, select the address reachable from your other device to change the QR code.

Enter the eight-digit code shown on the Mac. A code expires after five minutes; **New Pairing Code** replaces it without revoking existing browsers. Each paired browser has its own credential. The browser stores its credential locally and reconnects automatically while the server remains running. **Forget this browser** clears that browser's local credential. **Revoke** in desktop settings invalidates the selected session and cancels an active companion action. **Stop Companion** invalidates all sessions and invokes desktop cancellation for companion actions. After restarting, open the new displayed address and pair again. Sessions are intentionally never persisted by the Mac across stop or quit.

The deck shows the desktop's effective virtual layout, colors, labels, action descriptions, icons/artwork, current profile/page and execution feedback. Live ambient colors and action feedback update in place, keeping focused controls intact. Profile selection activates a runtime profile; **Auto** follows the desktop's automatic application selection. Assigned page and folder navigation uses the same desktop navigation logic. The virtual layout has 64 controls and remains independent of physical-device layouts. Editing happens in the desktop editor.

The desktop is authoritative. The browser polls idle snapshots every 800 milliseconds, checks at 67-millisecond intervals while lighting is animated or briefly after a press, and backs off while hidden. Pairing, activation and button presses trigger immediate synchronization. Each press includes the displayed revision and page ID; the desktop rejects stale presses rather than executing a newly changed assignment. Disconnection disables every control until a fresh snapshot arrives. This supports a paired phone alongside the selected MIDI device, while retaining the desktop's single action executor.

## Connection limits

This is local HTTP intended for a trusted private network. Do not forward the port to the Internet or use it on public Wi-Fi. No hosted service or account is involved. Origin and Host checks restrict browser calls to the displayed addresses; authentication is required for snapshots, actions, activation and artwork. Credentials travel in the Authorization header, never in URLs. Presentation snapshots exclude command source, file bookmarks and service secrets. Keyboard, scripting and service permissions remain enforced by the desktop.

The server accepts at most 32 paired browsers and 64 simultaneous TCP connections. Requests use bounded HTTP/1.1 framing: 8 KiB headers, 16 KiB bodies, no duplicate headers or transfer encoding, one request per connection, a five-second connection deadline, and bounded request rates (ten pairing attempts and 200 other requests per ten seconds per IPv4 host). Artwork responses are limited to 8 MiB. Malformed framing, unfamiliar hosts and foreign/cross-site origins are rejected before desktop action callbacks. The companion supports ordinary IPv4 local networks; IPv6-only networks are not yet advertised.

## Developer contract

`CompanionServer` is MainActor observable, backed by Network.framework. Its callbacks are `onSnapshot`, `onPress(index, revision, pageID)`, `onActivate(profileID)` (nil selects Auto), `onArtwork(assetID)`, and `onStop`. A callback error becomes an HTTP 409 response. The coordinator must validate snapshot revision/page/control identity and enforce its normal permissions, profile resolution, navigation and execution lifecycle. A snapshot contains presentation values only; do not serialize stored action recipes or credentials into action descriptions.

`GET /` serves an embedded, dependency-free client. `POST /api/pair` accepts `{code,name}` and returns a separate random bearer token/client ID. Authenticated routes are `GET /api/snapshot`, `GET /api/artwork/<id>`, `POST /api/press` with `{index,revision,pageID}`, and `POST /api/activate` with `{profileID}` or null for Auto. HTML artwork fetches use authenticated requests and local blob URLs. No server-side navigation paths or file-system paths are exposed.

`swift test --filter CompanionTests` exercises real loopback pairing, expiry, multiple sessions, revocation, stale presses, activation, protected artwork, restart invalidation, rate bounds, Host/Origin rejection, actual fragmented TCP requests and framing limits. Protocol tests do not establish behavior on a physical phone/tablet or your particular Wi-Fi/firewall. Browser QA used a non-executing 64-control fixture on the actual server, verifying a 390×844 phone viewport and a 1024×768 landscape tablet viewport, live feedback, Auto activation and disabled controls after server loss.
